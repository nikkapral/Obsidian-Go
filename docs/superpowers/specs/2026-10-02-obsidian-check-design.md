# Obsidian Check — дизайн

Дата: 2026-10-02

## Цель

Мобильное приложение для проверки знаний по заметкам Obsidian: пользователь выбирает категорию (путь в vault), получает колоду карточек с утверждениями и отвечает свайпами «верно/неверно» (механика Tinder). Карточки генерируются автоматически из содержимого заметок.

## Решения, принятые при обсуждении

- Источник карточек: **автогенерация из заметок** (ничего не размечается вручную).
- Доступ к vault: **плагин Obsidian + локальный HTTP-API**.
- Платформа: **кроссплатформа** — React Native (Expo).
- Генерация: **Kimi API (Moonshot)** из плагина, OpenAI-совместимый эндпоинт `chat/completions`.
- Логика сессий: **разовые сессии** со счётом в конце, без памяти между сессиями.
- Архитектура: **«толстый» плагин** — генерация, кеш и API на десктопе; приложение — тонкий клиент.

## Архитектура

```
┌─ Desktop: Obsidian ─────────────────┐        ┌─ Phone: Expo app ─────┐
│ Плагин Obsidian Check               │  LAN   │ Экран выбора колоды   │
│  settings → generator → store       │ HTTP   │ Экран сессии (свайпы) │
│  server (GET /decks, /decks/:path,  │◄──────►│ Экран результата      │
│         POST regenerate)            │        │ Настройки (IP:порт)   │
└──────────────────┬──────────────────┘        └───────────────────────┘
                   │ HTTPS
            Kimi API (Moonshot)
```

### Плагин Obsidian (TypeScript, официальный Obsidian API)

- **settings** — API-ключ Kimi, список отслеживаемых путей vault, порт сервера (по умолчанию 27124).
- **generator** — читает `.md` по отслеживаемым путям, отправляет текст в Kimi, получает JSON-массив карточек; 10–20 карточек на заметку, примерно половина — правдивые факты, половина — правдоподобные искажения.
- **store** — кеш колод в `vault/.obsidian-check/decks.json`; перегенерация только изменённых заметок (по mtime); атомарная перезапись кеша.
- **server** — локальный HTTP:
  - `GET /decks` — список колод (путей) с количеством карточек и флагом «устарела»;
  - `GET /decks/:path` — карточки колоды;
  - `POST /decks/:path/regenerate` — принудительная перегенерация.

### Мобильное приложение (React Native + Expo)

- **Экран выбора колоды** — первый экран: список категорий (путей) из `GET /decks`, значок «можно обновить» для устаревших.
- **Экран сессии** — стек карточек; свайп вправо = «верно», влево = «неверно»; после свайпа карточка подсвечивается зелёным/красным (правильность ответа). Сессия идёт полностью офлайн на телефоне.
- **Экран результата** — счёт и список ошибок (утверждение, правильный ответ, ссылка на заметку-источник).
- **Настройки** — IP:порт компьютера с Obsidian.

## Формат данных

Карточка: `{id, statement, isTrue, note, notePath}`
- `statement` — утверждение на экране;
- `isTrue` — верно ли утверждение по заметке;
- `note` — заголовок заметки-источника, `notePath` — её путь в vault.

## Потоки данных

1. Пользователь в плагине жмёт «сгенерировать» (или плагин видит изменённые заметки) → generator собирает заметки пути → Kimi возвращает карточки → store атомарно обновляет кеш.
2. Приложение при открытии тянет `GET /decks` → пользователь выбирает категорию → `GET /decks/:path` → сессия офлайн → результат показывается локально, никуда не отправляется.

## Обработка ошибок

- Нет связи с плагином → экран «Obsidian недоступен: проверьте IP и что Obsidian запущен», кнопка повтора.
- Kimi вернул ошибку/лимит → notice в Obsidian, кеш не трогаем.
- Невалидный JSON от Kimi → один ретрай с уточняющим промптом, затем заметка пропускается (лог).
- Заметка изменилась после генерации → колода помечается устаревшей; играть по старой можно.

## Тестирование

- Плагин: юнит-тесты на Vitest — парсинг ответа Kimi, обновление кеша, фильтрация по mtime; HTTP API мокается.
- Приложение: тест логики сессии (подсчёт очков, оценка ответа) + ручная проверка свайпов в Expo Go.

## Ограничения

- Телефон и компьютер в одной Wi-Fi сети; Obsidian запущен.
- Ключ Kimi хранится только на десктопе в настройках плагина.
